# SimpleForms ↔ Binatel

Внутренний сервис, который сопоставляет анкеты из [SimpleForms](https://simpleforms.ru) (CATI-опросы) со звонками из телефонии **7Line** (в проекте называется «Binatel») и позволяет скачать аудиозаписи звонков, соответствующих конкретным анкетам.

Продакшен: **https://simpleforms-binatel.vercel.app** (Vercel-проект `simpleforms-binatel`).

## Зачем это нужно

Заказчики периодически просят прислать аудиозаписи звонков по конкретному сегменту анкет (например, «Клиенты B2B ОВД, 160 анкет»). Вручную искать 160 записей в личном кабинете телефонии нереально — этот сервис делает это автоматически:

1. Сопоставляет анкеты SimpleForms со звонками 7Line по номеру телефона (и ближайшему по времени звонку, см. `matcher.ts`).
2. Даёт скачать все найденные записи одним ZIP-архивом — целиком по проекту или по списку номеров анкет из файла.

## Архитектура

```
backend/   Express + TypeScript, единая точка входа src/server.ts
  clients/
    simpleforms.ts   — клиент SimpleForms API (анкеты, проекты)
    binatel.ts        — клиент 7Line API (звонки, аудиозаписи).
                         Несмотря на название "Binatel" в проекте, реальный
                         бэкенд — https://1.7line.kz. Кеширует список звонков
                         на 10 минут (см. "Особенности и грабли" ниже).
  services/
    matcher.ts         — сопоставление анкет и звонков по телефону/времени
    archiver.ts         — потоковая сборка ZIP (archiver), скачивание записей
                          батчами по 5 параллельно, с ретраями
    exporter.ts         — экспорт таблицы анкет в CSV/XLSX
    formListParser.ts   — разбор загруженного xlsx/csv со списком номеров анкет
  routes/
    projects.ts   GET  /api/projects            — список проектов SimpleForms
    forms.ts      GET  /api/forms                — анкеты + сопоставленные звонки
    export.ts     GET  /api/export/csv|xlsx       — выгрузка таблицы
    archive.ts     GET  /api/archive              — архив всех записей проекта(ов)
                    POST /api/archive              — архив по списку номеров анкет
                    POST /api/archive/parse-file   — парсинг xlsx/csv в список номеров
    recording.ts  GET  /api/recording/:callId     — проксирует аудио для плеера
frontend/  Ванильные HTML/CSS/JS (без сборки), раздаются статикой из backend
```

Деплой — один serverless-билд на Vercel (`@vercel/node`, `maxDuration: 300s`, см. `vercel.json`). Локально: `cd backend && npm run dev` (порт из `.env`, по умолчанию 3000).

## Как скачать архив записей по сегменту анкет

Так возникла эта инструкция: периодически нужно скачать аудио по xlsx-файлу вида «Сегмент Клиенты B2B ОВД 160 анкет.xlsx», который выгружается из другой системы и содержит колонку `№ Анкеты` или `ID Анкеты`.

1. Открыть https://simpleforms-binatel.vercel.app
2. В списке «Проекты» отметить нужный проект SimpleForms.
   ⚠️ **Название сегмента в файле не всегда совпадает с названием проекта.** Сегменты — это подмножества более крупного проекта в SimpleForms (проект содержит все волны/сегменты сразу, xlsx-файл — конкретную выборку из него). Ориентироваться нужно по теме опроса, а не по числу анкет в названии. Например, файл «...B2B ОВД 160 анкет» (ОВД = облачное видеонаблюдение) соответствует проекту **«B2B NPS Видеонаблюдение (564 анкеты)»** — это тот же опрос про облачное видеонаблюдение Казахтелеком, только полный проект включает несколько сегментов/волн. Есть также похожий проект «B2B NPS Видеонаблюдение (КОНКУРЕНТЫ) (100 анкет JUSAN)» — это **другой** опрос (про конкурентов), с ним легко перепутать по названию.
   Если непонятно, какой проект выбрать — открыть анкету xlsx и свериться с текстом вопросов, либо посмотреть на диапазон дат/номера анкет.
3. В блоке «Архив записей по списку номеров анкет» нажать «📄 Загрузить список из файла (XLSX/CSV)» и выбрать xlsx-файл сегмента — сервис сам вытащит номера анкет.
4. Нажать «⬇ Скачать архив по списку». Появится спиннер и статус «Архив собирается на сервере…».
5. Когда сборка на сервере закончится, браузер сам начнёт скачивание ZIP (`recordings_<имя проекта>.zip`) — дальше прогресс виден в панели загрузок браузера. Внутри архива — mp3 по каждой анкете со звонком и `_отчёт.txt` со статистикой (сколько запрошено/найдено/со звонком).
6. Если номеров > 800 — список бьётся на части (`ARCHIVE_PART_SIZE` в `app.js`), части запрашиваются последовательно с паузой 12 с, каждая скачивается отдельным архивом.

### Наблюдения по скорости

Время до начала скачивания сильно зависит от того, «прогрет» ли серверный кеш звонков (10 минут, см. `binatel.ts`):

- **Кеш тёплый** (в проект недавно уже загружали таблицу/архив на том же диапазоне дат, и Vercel-инстанс не успел «уснуть») — сборка архива почти мгновенная. Так был скачан архив по 160 анкетам (ОВД) 2026-08-07: после выбора проекта и загрузки xlsx весь процесс от клика до готового ZIP занял **~20–30 секунд**, итоговый файл — 55 МБ, все 160/160 анкет нашли звонок.
- **Кеш холодный** (первый запрос к проекту с широким диапазоном дат анкет, например после рестарта локального сервера) — 7Line отдаёт звонки постранично (по 100 шт., чанками не более 31 дня), и на проекте с большим диапазоном дат это может занять **несколько минут**. При локальном тесте на холодную по проекту «564 анкеты» запрос не уложился даже в 290 секунд (сработал клиентский safety-timeout, см. ниже) — вероятно, потому что диапазон дат анкет в этом проекте охватывает много волн/месяцев.
- Именно поэтому в `app.js` для запроса по списку номеров стоит защитный таймаут на 290 с (чуть меньше лимита Vercel-функции в 300 с) — если сборка не отозвалась и за это время, пользователю показывается сообщение с просьбой проверить папку загрузок или повторить попытку, вместо вечно крутящегося спиннера.

## Особенности и грабли

- **`archiveStream` начинает отдаваться сразу**, но реальная тяжёлая часть (запрос анкет+звонков в `loadRecords()`) выполняется *до* начала отдачи файла — именно поэтому раньше пользователь не видел вообще никакой обратной связи, пока шла эта фаза (отсюда и появился спиннер на списке номеров, см. ниже).
- **Скачивание файла через скрытый `<iframe>` + `<form target="...">`** (а не `fetch`) — сделано специально, чтобы не держать сотни мегабайт/гигабайт архива в памяти браузера (`app.js`, комментарий в `submitArchiveRequest`). Из-за этого у скачиваний с `Content-Disposition: attachment` **не срабатывает `load`-событие iframe** — Chrome перехватывает такой ответ как download, а не как навигацию, и в документ он не коммитится (проверено эмпирически через `javascript_tool` в этой сессии). Поэтому для отслеживания сборки архива используется отдельный сигнал — см. ниже.
- **Как сервер сообщает фронту, что сборка завершилась**: клиент генерирует одноразовый токен и передаёт его как `downloadToken` в теле POST-запроса; сервер (`sendArchive()` в `archive.ts`) устанавливает cookie `dl_<token>` прямо перед началом отдачи файла. Фронт поллит `document.cookie` каждые 400 мс — как только cookie появилась, значит сборка закончилась и скачивание пошло, спиннер гасится.
- **Если сервер вернул JSON с ошибкой** (а не файл) — это обычная навигация, и `load` у iframe срабатывает **дважды**: первый раз сразу при вставке iframe в DOM (служебная загрузка `about:blank`, ничего общего с запросом), второй — уже с реальным ответом. Код в `submitArchiveRequest` игнорирует первое срабатывание и по второму читает `iframe.contentDocument` как JSON, чтобы показать текст ошибки.
- **7Line периодически отвечает 5xx под нагрузкой** — `binatel.ts` ретраит с экспоненциальной паузой; `archiver.ts` качает сами аудиозаписи батчами по 5 параллельно (больше — сервер 7line начинает падать) с 3 попытками на файл.
- **SimpleForms API отвечает 503 при параллельных запросах анкет** — поэтому в `loadRecords()` (`archive.ts`) анкеты нескольких проектов запрашиваются строго последовательно, не через `Promise.all`.

## Переменные окружения

См. `.env.example`: `SIMPLEFORMS_API_KEY`, `SIMPLEFORMS_API_BASE`, `SIMPLEFORMS_API_VERSION`, `BINATEL_API_KEY`, `BINATEL_API_BASE` (в проде указывает на `1.7line.kz`), `PORT` (для локального запуска).
